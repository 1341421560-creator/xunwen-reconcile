# 网商银行流水导入更新

本次将网商银行企业账户交易明细接入累计账本的统一导入流程。交通银行与网商银行格式均可用于当前配置的所有公司；格式配置不包含真实公司名称、账号或交易数据。公司仍分别保存账本，导入时核验企业全称。

## 使用步骤

1. 启动软件，在顶部选择对应公司。首次启用公司时，填写银行文件中的完整企业名称并确认。
2. 点击“导入文件”，在“银行对公流水”中选择银行导出的原始 `.xls` 或 `.xlsx` 文件。
3. 软件自动识别银行格式；流水与进项发票仍支持分别导入或同时导入。
4. 在“导入记录 → 批次来源与导入检查”查看格式识别、金额合计、交易笔数以及新增、重复、冲突数量。
5. 后续月份继续追加流水或发票，已保存的跨月匹配、分批开票进度和人工关联继续使用。

一份文件可以覆盖多个月。月份筛选只影响显示，不影响历史匹配范围。交通银行、网商银行的不同账户可以保存在同一公司的账本中；另一家公司的文件不能混入。

## 网商银行字段和检查

| 文件内容 | 软件处理 |
|---|---|
| 浙江网商银行企业账户交易明细 | 识别银行格式 |
| 企业名称 | 与当前公司完整名称核对 |
| 企业账号，例如 `8888000000000001(人民币)` | 提取账户并确认人民币；保留前导零 |
| 账务流水号 | 保留完整文本，作为去重依据的一部分 |
| 交易时间 | 使用实际交易日期；提交时间为空不影响导入 |
| 借方金额(收) | 收入，内部记入收入字段 |
| 贷方金额(支) | 支出，内部记入支出字段 |
| 对方户名、对方机构、交易名称、备注、余额 | 保留对应交易资料 |
| 页头借方/贷方交易金额与笔数 | 分别核验实际收入/支出的金额和笔数 |

网商银行列名中的“收/支”决定金额方向，与交通银行原模板的借贷映射不同。收入继续沿用“不参与进项比对”的现有规则。

所有交易行均按表头读取，不按固定交易笔数截断。空行和一致的分页表头不计入交易。表头缺失、重复金额列、分页列顺序改变、金额或笔数不一致、公司不符、账号或流水号精度异常、非法日期及金额，都会拒绝整次导入。

重复记录沿用“同一公司内的银行账号＋银行流水号”识别；重复导入只追加来源。相同编号内容变化进入冲突核对。缺少流水号时仍执行现有疑似重复复核规则。

支持范围为已验证的交通银行固定模板及网商银行企业账户交易明细模板，人民币对账。单文件上限仍为 20 MB，单工作表上限仍为 30,000 行；累计账本不受单次文件行数限制。

## 验证结果

- 新增网商银行自动测试 24 项，全部通过：四个公司分别导入、任意合法公司名与账号、跨月匹配、收支方向、空提交时间、完整流水号、重复及覆盖月份导入、冲突、异常回滚、重复表头及 1,000 行读取等。
- 全部 Python 测试共 249 项：247 项通过、0 项失败，2 项默认依赖外部验收材料的测试跳过。
- 其中交通银行与发票模板各 1,000 行的分页累计导入测试已另行提供已有样例补跑并通过。因此本轮共验证通过 248 个不同测试；旧历史迁移基准未在本轮执行，软件仓库不携带该真实历史材料。
- 10,000 笔历史付款与 10,000 张新增发票的累计匹配测试通过。
- 网商银行原文件浏览器验收通过：逐行独立核算、实际上传、重复上传、月份筛选、导入检查展示、支出统计、选错公司拒绝及重启读取。
- 原有多公司浏览器验证的 10 个场景全部通过，包括公司启用与切换、未保存提示、旧页面提交拒绝、核对备注隔离和导出。

真实文件与隔离测试账本仅用于本机验证，不进入 Git 软件仓库或软件包。浏览器验收目录和测试日志保存在项目 `temp/` 下。

## 开发与复验

无新增运行依赖，沿用整合版的 Windows x64 离线环境。

使用整合版环境运行 `scripts/entry.py test --pattern test_mybank.py` 可复验网商银行测试。现有 `browser-check` 验证多公司流程。

新增 `mybank-browser-check --source <原始网商文件路径> --company-name <完整企业名称>` 用于本地原文件验收。通过 `scripts/entry.py` 调用，需开发用 Node.js、Playwright 和 Edge；这些工具仅用于浏览器测试，日常使用软件无需安装。
