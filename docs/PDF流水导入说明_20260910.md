# 交通银行电子 PDF 流水导入

银行流水导入增加交通银行电子 PDF 支持。所有公司账本共用格式识别流程，按文件里的企业名称、银行账户和人民币标识核验归属；无需为每家公司另行设置解析规则。

## 使用方法与范围

1. 启动整合版，选择对应公司。
2. 点击“导入文件”，在“银行对公流水”中选择完整的交通银行电子 PDF 对账单。
3. 点击“导入并匹配累计账本”。成功后查看新增、重复和冲突数量。
4. 在“导入记录 → 批次来源与导入检查”查看页数、交易笔数、收支合计及校验结果。

| 导入内容 | 支持格式 |
|---|---|
| 交通银行对公流水 | 原有 Excel 模板；本次适配的电子 PDF 明细对账单 |
| 网商银行对公流水 | 原有 Excel 模板 |
| 进项发票清单 | 原有 Excel 模板 |

PDF 需要包含可读取的文字、完整表格线、企业名称、账号、人民币标识、年月与页码、承前余额，以及最后一页的月度金额和交易笔数控制信息。单份 PDF 应为同一公司、同一账户、同一月份的完整对账单，不能合并不同账户或月份，也不能只导出其中几页或部分交易。

扫描图片、加密 PDF 和其他未适配银行或版式会明确提示，整次导入取消。PDF 的支持范围以银行原始电子明细对账单为准，不能仅将其他文件改名为 `.pdf`。

单文件仍不超过 20 MB。Excel 单工作表不超过 30,000 行；PDF 最多 200 页、30,000 笔交易。PDF 内容解压后也设有资源限制，超过限制时提示拆分，避免只导入前面的数据。累计账本不受单次文件条数限制。

## 如何保证金额和记录完整

- 从表格边界还原行列，按列名读取交易日期、对方户名、摘要、流水号、借方发生额、贷方发生额和余额。
- 只转换提取出的页面坐标，不重写原 PDF 内容或字体映射；支持对应版式的页面旋转。
- 拼接同一单元格内的换行文字；流水号始终作为文本保存。
- 逐页核对公司、账号、币种和账期；页码及交易序号必须连续。
- 每笔验证“上一笔余额＋收入－支出＝本笔余额”，承前和结转余额也必须相符。
- 整份文件的借贷金额合计、当前账单笔数及本月累计笔数均须与控制信息一致。
- 文件名、文件哈希、PDF 页码、表格行号及交易序号保留为来源依据。

出现缺页、重复页、错列、缺少金额、日期异常或校验失败时，不提交本批次数据。同一批次选择了流水和发票时，其中一份失败会取消整批导入。

PDF 与 Excel 共用现有的账号及流水号去重、冲突核对、跨月匹配、分批核销和撤回流程。相同交易及内容再次导入只增加来源；同一编号的金额或其他实质内容不一致时保留原记录并进入冲突核对。缺失流水号仍沿用疑似重复复核流程。

## 离线环境

新增固定版本 `pypdf 6.18.0` 原始 wheel，保存在 `downloads/`，大小和 SHA-256 锁定在 `config/runtime.json`；许可证副本位于 `docs/licenses/`。

运行环境升级为 `xunwen-reconcile-py31210-win-x64-pdf-v2`。启动脚本从随附离线包在统一环境目录准备该版本，不需要额外安装 PDF 阅读器或下载解析组件。已有旧版本环境保留，避免影响旧软件副本。

第三方组件来源：[pypdf 官方发行页](https://pypi.org/project/pypdf/6.18.0/)。文字和坐标提取接口参考：[pypdf 官方文档](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。

## 验证结果

新增 24 项 PDF 测试全部通过，覆盖以下场景：

- 收支方向、金额与笔数控制、逐笔余额、完整来源定位。
- 中文、英文换行拼接与长流水号；四种页面旋转。
- 多页结转以及 125 页、1,000 笔交易完整读取。
- 缺页、重复页、乱序页、缺失交易、重复交易和序号断档。
- 金额、余额、承前金额、控制数、日期、币种及身份信息异常。
- 跨页公司、账户或账期变化；缺少表头、表格边界或控制信息。
- 扫描空白页、加密文件、损坏文件、伪装扩展名和资源上限。
- PDF 放入发票入口、双文件导入中一份出错时整批回滚。
- PDF 重复导入、PDF 与 Excel 交叉导入、同编号冲突和缺少流水号。
- 四家公司共用 PDF 导入；跨月分批核销、重启和重复导入后进度保留。

完整测试共 273 项，272 项通过、0 项失败、1 项旧真实历史迁移测试未启用。包含原有交通银行及发票各 1,000 行分页导入和 10,000 笔历史付款与 10,000 张新增发票匹配测试。

用户提供的 PDF 已通过独立逐行核算和浏览器实际导入、重复上传、月份筛选、公司校验、支出统计及重启读取验证。网商银行 Excel 原文件也通过相同浏览器流程复验。测试只使用隔离账本，正式账本哈希与更新前一致。

PDF 误放入发票入口时的页面提示和不提交行为已验证。原有多公司浏览器流程的 10 个场景也全部通过，包括同时导入流水与发票、公司切换、未保存表单、过期页面提交拒绝、备注隔离与导出。

## 代码及复验入口

主要新增模块为 `reconcile/pdf_reader.py`（PDF 读取和资源限制）、`reconcile/pdf_geometry.py`（坐标和文字拼接）、`reconcile/pdf_table.py`（表格和标签还原）、`reconcile/bocom_pdf_import.py`（交通银行记录转换）、`reconcile/bocom_pdf_controls.py`（账单完整性与金额校验）。模板参数在 `config/pdf_import.json`。

测试文件为 `tests/pdf_fixtures.py`、`tests/test_pdf_import.py`。使用整合版环境运行 `scripts/entry.py test --pattern test_pdf_import.py` 可以复验。

原文件浏览器验收入口为 `scripts/entry.py pdf-browser-check --source <银行原件> --expected <独立逐行预期JSON>`。PDF 与网商银行复用 `scripts/bank_browser_support.py` 和既有的 `tests/browser_mybank.cjs` 银行导入流程。浏览器复验需要开发用 Node.js、Playwright 与 Edge，日常运行软件无需这些开发工具。

软件包只包含代码、配置、离线环境和不含真实公司资料的测试夹具。原 PDF、逐笔预期结果、隔离账本、页面截图和测试日志保存在本机 `temp/`，不进入软件 Git 仓库及整合包。
