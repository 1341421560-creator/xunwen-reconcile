# 开发与验证说明

所有常规运行入口通过 `scripts/entry.py` 组装所需路径，并使用内嵌 Python 的隔离导入路径。不读取用户现有 Python 环境，不调用 pip，也不依赖 Node 构建。

项目路径均以软件根目录解析。唯一固定的外部安装根目录为用户约定的 `C:\env`，集中在 `config/runtime.json`。运行中的账本、会话和报表写入当前软件目录，缓存和测试文件写入 `temp/`。Python 字节码缓存关闭。

## 执行测试

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test.ps1 -Pattern test_distribution.py
```

测试结果按次写入 `temp/tests-日期-随机号/results.json` 与 `test-output.txt`。每项标记 passed、failed 或 skipped。保留中断现场，不自动删除临时文件。

以下两项可选私有数据验证不在公开仓库默认运行：

- `test_19_migration_interrupt_idempotence_and_real_baseline`：需要原始交通银行 Excel、进项发票 Excel，以及软件 `sessions/` 中相应旧版会话。设置 `RECON_BANK_SOURCE`、`RECON_INVOICE_SOURCE` 为原始文件路径后启用；只在临时账本中迁移。
- `test_24_fixed_templates_paged_cumulative_import`：设置 `RECON_CAPACITY_DIR` 为已有 `bank_1000_paged.xls` 和 `invoice_1000_paged.xlsx` 的验证目录后启用。

`scripts/verify_import_capacity.py` 保留固定模板容量生成与检查流程。这项可选开发工具还需要 LibreOffice 和原始模板；LibreOffice 不属于软件运行依赖，也不包括在离线包内。运行前用其 `--help` 查看必填参数。

## 数据与运行环境

业务配置在 `config/defaults.json`。账本已存在后不能随意更换公司名称或数据目录，否则会触发身份检查；迁移恢复使用默认数据目录。端口可通过启动参数覆盖，无需改动公司规则。

环境准备由 `scripts/Environment.psm1` 完成：先验证压缩包，再持有同一版本的 Windows 互斥锁，复用文件哈希匹配的安装，或从档案创建完整的新安装。生成完整安装清单后才标记为可用；中断或损坏的安装不会直接复用。

启动互斥锁按项目目录和端口区分。进程记录包含 PID、启动时间与当前入口路径，停止时核对身份，避免 PID 重用或不同目录服务被误停。

账本备份保留原始 JSON 字节，独立附加每个文件的哈希清单。恢复先检查整个包与目标冲突，再在项目 `temp/` 暂存并同步文件，账本最后原子发布。相同文件跳过，不同内容拒绝覆盖。

## 发布注意

日常发布应包含整个 Git 跟踪集合，尤其不要漏掉 `downloads/` 的运行包和 wheel。不要从现有虚拟环境复制 `site-packages`；它不构成可移植环境。

新版本需要调整离线环境时，先准备新的官方运行包及 wheel，更新版本标识、来源、大小和 SHA-256，保留原始许可证，然后执行自检、全部测试和全新 clone 的启动验证。环境更新不应覆盖其他任务的 Python 目录。
