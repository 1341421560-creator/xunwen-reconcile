# 循文对账 · Windows 离线整合版

这是供深圳市摩德瑞特科技有限公司使用的本机对账软件。导入交通银行对公流水和进项发票清单后，在浏览器中查看已匹配、部分匹配、未匹配、待确认和不参与比对的记录。账本持续累积，支持跨月、跨年开票及分批金额核销。

**仓库包含 Python 运行包、全部运行依赖、源码和测试。另一台 Windows 电脑完整 clone 后，双击启动即可；首次启动无需联网下载，也无需另装 Python、pip、Node.js、Excel 或数据库。**

## 在新电脑启动

1. 使用 **Windows 10 / 11，Intel 或 AMD 的 64 位电脑**。需要浏览器，以及当前用户对软件目录、`C:\env` 的写入权限。此离线运行包不支持 macOS、Linux、Windows 32 位或 ARM64。
2. 完整 clone 仓库；也可下载软件 ZIP 并解压。不要在 ZIP 压缩文件预览中直接启动。建议使用较短目录，例如 `D:\apps\xunwen-reconcile`。
3. 双击 **`启动对账软件.cmd`**。首次启动会校验仓库里的四个离线包，再在 `C:\env\xunwen-reconcile-py31210-win-x64-v1` 准备独立运行环境。后续启动复用校验通过的环境。
4. 浏览器自动打开 **http://127.0.0.1:8765**。首次 clone 是空账本，可导入新的流水或发票，也可先恢复单独保存的旧账本迁移包。
5. 用完后双击 **`停止对账软件.cmd`**。关闭网页标签不会停止后台服务。

首次准备只使用仓库内的文件，不修改系统 PATH，不安装到已有 Python 环境。若准备被中断或安装文件损坏，会保留原目录，在同一 `C:\env` 下建立带 `repair` 后缀的独立环境。

## 常用入口

| 入口 | 用途 |
|---|---|
| `启动对账软件.cmd` | 准备环境、启动本机服务并打开浏览器 |
| `停止对账软件.cmd` | 停止由当前软件目录启动的服务 |
| `检查运行环境.cmd` | 检查环境、依赖、写入权限、账本完整性 |
| `运行全部测试.cmd` | 使用附带解释器运行回归和异常测试 |
| `备份账本数据.cmd` | 将账本、旧记录、历史报表打成独立迁移包 |
| `恢复账本数据.cmd` | 输入迁移包路径，将数据恢复到新软件目录 |

入口失败时窗口会保留错误提示。运行日志、环境自检结果和测试记录在 `temp/`。软件只监听本机地址；启动脚本不会停止或接管其他目录的服务。

## 旧电脑数据带到新电脑

软件和数据分开保存。**Git 仅包含软件和离线环境，真实流水、发票、账本和导出报表不会自动进入版本库。**

1. 旧电脑双击 `备份账本数据.cmd`，在 `data-transfer/` 得到 ZIP 迁移包。
2. 单独将该 ZIP 带到新电脑。包内包含真实业务数据，按公司资料管理，不提交 Git。
3. 在新电脑全新 clone 的目录中，双击 `恢复账本数据.cmd`，粘贴 ZIP 路径。
4. 恢复完成后启动软件；付款、发票、匹配金额、名称映射、撤回限制、来源和核对日志全部随账本保留。

恢复会校验公司、账本格式、版本和每个文件的 SHA-256。目标已有不同内容时停止，避免覆盖另一份账本。同一个迁移包可重复执行；恢复中断后，可在同一目录重新执行。恢复不是合并两台电脑各自新增的数据：需要迁移新版本账本时，请使用新的软件目录。多台电脑各自保存本机账本，Git 不提供账本同步。

迁移包包含解析后的账本、旧记录及历史报表；原始银行 Excel、原始发票 Excel 如需归档，请另行保存。当前迁移工具最多处理 20,000 个 ZIP 条目、512 MiB 解压内容，超过时会明确拒绝。

首次从旧版软件备份，也可以运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup.ps1 -SourceRoot "..\循文对账"
```

## 对账规则与使用范围

- 每次至少导入一份文件；可以只导入流水、只导入发票，也可同时导入。
- 按公司、银行账户、银行流水号，以及公司、发票代码、发票号码识别重复。疑似重复、编号冲突和异常票进入核对。
- 自动匹配要求名称或已确认映射、币种、剩余金额一致，且双方唯一对应。月份筛选只影响显示。
- 分批开票、金额不等或有多个候选时，人工填写分配金额和依据；支持一票多付、多票一付，禁止超额核销。
- 收入、工资、税费、社保公积金、网银服务年费、网银证书服务年费保留现有分类。
- 支持固定交通银行流水模板、固定进项发票清单；单文件不超过 20 MB，单工作表不超过 30,000 行。这些限制不等于累计账本容量上限。
- 当前为本公司、人民币、单机使用。红字票、作废票及状态冲突需要人工复核。

## Git 提交与后续更新

`downloads/` 中的四个文件是运行必需项，需和源码一起提交；最大单文件约 10.62 MiB，不需要 Git LFS。

`.gitignore` 已排除 `ledger/`、`sessions/`、`reports/`、`backups/`、`data-transfer/`、`temp/`、`output/`、Excel/CSV 和本机配置。不要用 `git add -f` 强行提交这些业务文件。项目保留本公司的名称配置，但不包含实际账户、流水和发票数据。

当前交付仓库已在本地 `main` 上整理，尚未配置远端。确认目标仓库后，在本目录执行：

```powershell
git remote add origin <你的仓库地址>
git push -u origin main
```

这两条命令适用于新的空远端；已有内容的远端请先检查历史，不要强制推送。日后更新代码前先备份账本、停止服务，再执行 `git pull --ff-only`，完成后重新启动。不要直接修改已锁定的离线运行包；升级依赖时应重新构建、记录哈希并验证。

## 测试与排查

双击 `运行全部测试.cmd` 可在断网环境执行常规测试，覆盖匹配、重复导入、异常文件、并发、写入中断、数据恢复和 10,000 笔历史流水与 10,000 张新发票。

原有测试中两项依赖公司原始 Excel、旧会话及固定模板容量夹具，空仓库默认明确跳过；这些私人资料不随 Git 交付。可选验证方法见 [开发与验证说明](docs/开发与验证说明.md)。跳过不计为通过。

遇到端口占用，先停止对应的原版软件，或者使用不同端口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1 -Port 8766
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop.ps1 -Port 8766
```

如果无法写入 `C:\env`，请由电脑管理员为当前用户授予该目录的写入权限后重试；脚本不会自动提权。若公司设备策略禁止 PowerShell，需管理员允许运行本软件脚本。不要为了启动而关闭安全软件。

## 项目结构与第三方组件

| 目录 | 内容 |
|---|---|
| `reconcile/` | 导入解析、身份去重、账本存储、匹配、核销、审计、迁移与导出 |
| `web/` | 无构建步骤的浏览器页面与交互模块 |
| `deployment/` | 运行检查、测试执行、迁移包校验、备份与恢复 |
| `scripts/` | 启动、停止、检查、测试和数据工具入口 |
| `config/` | 业务默认配置、运行包版本和下载来源及哈希 |
| `downloads/` | 官方 Python 运行 ZIP 和三个锁定版本的依赖 wheel |
| `tests/` | 不依赖真实财务数据的常规回归及异常测试；保留可选私有数据验证 |
| `docs/` | 开发说明、第三方许可证与交付验证报告 |

版本为 Python 3.12.10、xlrd 2.0.2、openpyxl 3.1.5、et_xmlfile 2.0.0。离线环境采用 [Python 官方 Windows 可嵌入发行包](https://www.python.org/ftp/python/3.12.10/)，各文件来源、长度、SHA-256 固定在 `config/runtime.json`。第三方原始许可证保存在 `docs/licenses/`，详见 [第三方组件说明](docs/第三方组件说明.md)。
